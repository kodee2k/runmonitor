# runmonitor

A local wandb-style experiment tracker with a live web dashboard.
Drop-in Python module — import it, and you get logging + a dashboard on port 8080.


Quickstart
----------

```python
import runmonitor as rm

run = rm.init(
    project="mnist-experiment",
    config={"lr": 0.001, "batch_size": 32},
    total_steps=1000       # optional, enables progress bar
)

for step in range(1000):
    loss, acc = train_step()
    run.log({"loss": loss, "accuracy": acc}, step=step)

run.save("model_final.pth")
run.finish()
```

Open http://localhost:8080 to see the live dashboard.

----------------

SQLite schema
-------------

```sql
CREATE TABLE projects (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL UNIQUE,
    created_at  TEXT    DEFAULT (datetime('now'))
);

CREATE TABLE runs (
    id           TEXT     PRIMARY KEY,   -- uuid4
    project_id   INTEGER  NOT NULL REFERENCES projects(id),
    name         TEXT,
    status       TEXT     DEFAULT 'running',  -- running | finished | crashed
    config_json  TEXT     DEFAULT '{}',
    total_steps  INTEGER,
    started_at   TEXT     DEFAULT (datetime('now')),
    finished_at  TEXT
);

CREATE TABLE metrics (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id      TEXT    NOT NULL REFERENCES runs(id),
    step        INTEGER NOT NULL,
    key         TEXT    NOT NULL,
    value       REAL    NOT NULL,
    timestamp   TEXT    DEFAULT (datetime('now'))
);

CREATE INDEX idx_metrics_run_step ON metrics(run_id, step);
CREATE INDEX idx_metrics_run_key  ON metrics(run_id, key);
```

Database lives at ~/.runmonitor/runs.db by default.


Server API
----------

Server starts automatically in a daemon thread on the first `import runmonitor`.

| Method | Endpoint                                | Purpose                    |
|--------|-----------------------------------------|----------------------------|
| GET    | /                                       | Serve dashboard.html       |
| GET    | /api/projects                           | List all projects          |
| GET    | /api/runs?project=NAME                  | List runs, optional filter |
| GET    | /api/runs/<run_id>/config               | Get run hyperparameters    |
| GET    | /api/runs/<run_id>/metrics              | All metrics for charting   |
| GET    | /api/runs/<run_id>/metrics?key=loss&limit=500 | Filtered, capped    |

OPTIONAL (phase 2):
| GET    | /api/runs/<run_id>/metrics/live?since=STEP | Polling since last step |


Core API — runmonitor/__init__.py
--------------------------------

rm.init(project, name=None, config=None, total_steps=None) -> Run
    Creates or reuses a project row.
    Inserts a run row with id = uuid4().
    Returns a Run instance.

run.log(metrics: dict, step: int)
    Inserts one row per key into metrics.
    step is the x-axis (epoch, batch, etc.).
    Batched insert for performance.

run.save(filepath: str)
    (Phase 2) Copies or symlinks artifact file.
    Records artifact row (schema TBD).

run.finish()
    Sets status = 'finished' and finished_at.

run.fail()
    Sets status = 'crashed' and finished_at.


Dashboard (templates/dashboard.html)
------------------------------------

Single-page app, no build step. Uses Chart.js from CDN.

Layout:

+-----------------------------------------------------------+
|  runmonitor                           [refresh]  [theme]  |
+-----------------------------------------------------------+
|  Project: [dropdown]    Run: [dropdown]                   |
+-----------------------------------------------------------+
|  [progress bar if total_steps set]                        |
+------------------+------------------+---------------------+
|  loss (line)     |  accuracy (line) |  Summary stats      |
|                  |                  |  - best loss        |
|                  |                  |  - current acc      |
|                  |                  |  - elapsed time     |
|                  |                  |  - steps/sec        |
+------------------+------------------+---------------------+
|  Hyperparameters table                                     |
+-----------------------------------------------------------+

UI features:
- Auto-refresh every 2 seconds via polling /api/runs/<id>/metrics
- Chart.js line charts, one canvas per metric key (or multi-line toggle)
- Progress bar = max(step) / total_steps as percentage
- Theme toggle: light <-> dark
- Run comparison: select 2 runs, overlay their loss curves in one chart

Gamification ideas:
- Streak counter: consecutive steps where loss decreased -> fire emoji
- Color-coded metric tiles: green (improving), yellow (flat), red (diverging)
- "Personal best" badge when loss hits a new minimum
- Step velocity: steps logged per second, displayed as a speedometer


Implementation order
--------------------

Phase 1 — Working MVP (build this first)
1. storage.py — schema + init_db(), insert/query helpers
2. server.py — Flask app, all API routes, serves dashboard
3. __init__.py — init(), Run class with log() and finish()
4. templates/dashboard.html — basic dashboard: project/run picker, two charts, polling
5. Manual integration test

Phase 2 — Polish
6. Artifact saving (run.save())
7. Run comparison overlay in dashboard
8. Gamification elements (streaks, badges, color coding)
9. System metrics thread (CPU, GPU, RAM)
10. Export to CSV / JSON button in dashboard


Design decisions
----------------

- Flask, not FastAPI — simpler, no async needed, one dep.
- SQLite only — no Postgres, no config burden for the user.
- Daemon thread — server starts silently, dies with the script.
  No `runmonitor serve` command needed.
- Polling, not WebSockets — simpler for MVP. SSE can come later.
- Single-file dashboard — everything in one HTML file with CDN deps.
- No pandas/numpy dependency — keeps the module light.
- Thread-safe SQLite — uses check_same_thread=False with WAL mode,
  writes serialized through a lock.
